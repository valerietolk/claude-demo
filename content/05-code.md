# Claude Code

**Что это:** Claude, который работает не только в чате, а прямо с файлами, кодом, репозиториями и подключёнными инструментами. Он может читать проект, менять файлы, запускать приложение, проверять результат и повторять цикл, пока задача не будет выполнена. Ну и накодить знатно)

Для дизайнера это не «научиться программировать», а получить возможность самостоятельно двигать всё, что раньше требовало разработчика: прототипы, плагины, внутренние инструменты, автоматизацию и небольшие изменения в продукте.

#### 1. Figma → работающий фронтенд

С подключённым Figma-коннектором:

> «Сверстай этот фрейм [ссылка на Figma] с нашими токенами и компонентами».

Claude получает структуру макета и может использовать её как источник для кода, а не пытаться восстановить интерфейс по скриншоту.

#### 2. Код → Figma

Можно взять существующий интерфейс и перенести его в редактируемый дизайн:

> «Вот наш сайт. Перенеси эту страницу в Figma: нашими компонентами, переменными и Auto Layout».

Получаем не картинку, а редактируемый макет.

#### 3. Массовые операции в Figma

> «Переименуй все слои по нашей конвенции».
>
> «Создай переменные из этого JSON».
>
> «Сделай компонент кнопки со всеми размерами и состояниями».

То, что обычно превращается в унылый день ручной работы, можно автоматизировать скриптом или плагином.

#### 4. Свой плагин

Можно попросить Claude Code сделать собственный инструмент:

> «Сделай Figma-плагин, который проверяет контраст текста на выделенном фрейме и подсвечивает проблемные места».

То же самое работает для проверки отступов, заполнения реалистичными данными, массового переименования, экспорта и других командных правил.

#### 5. Сам поправить UI в продукте

> «В репозитории продукта поменяй отступ у карточки на 16 и текст кнопки на "Сохранить изменения". Покажи, как выглядит».

Claude вносит правку, показывает результат в браузере и готовит изменения на ревью разработчикам.

Визуальные мелочи из бэклога, которые «никогда не доходят до спринта», дизайнер закрывает сам. Обязательно договоритесь с разработкой о процессе: правки идут через их ревью, а не напрямую в продукт.

#### 6. Прототип, который проверяет сам себя

> «Сделай прототип оформления заказа. Потом открой его в браузере, пройди основные сценарии и исправь всё, что сломано».

Claude Code может работать с браузерными инструментами через MCP и использовать результат проверки для следующего шага. Это уже не просто генерация, а цикл:

build → test → fix → test.

#### 7. Несколько генераций одновременно

> «Сделай три версии главной: минималистичную, редакционную и плотную».

Claude Code может использовать параллельных агентов для независимых задач.

Не нужно ждать три последовательных генерации — можно исследовать несколько направлений одновременно.

#### 8. Ресёрч → готовый результат

Папка с интервью:

> «Разбери все расшифровки, найди боли с цитатами, сгруппируй их и собери итоговый документ».

Claude Code особенно силён там, где нужно обработать много файлов и связать несколько инструментов через MCP.

#### 9. Автоматизация рутины

> «Вот 400 SVG. Оптимизируй, переименуй по конвенции, разложи по категориям и сделай страницу-превью».

Или:

> «Собирай новые отзывы о приложении раз в неделю и делай сводку».

Главная идея: если ты можешь точно описать повторяющуюся задачу, её часто можно превратить в автоматический процесс и настроить по расписанию.

#### 10. Анимация и generative graphics через код

Claude Code может создавать: procedural animation; shaders; generative graphics; интерактивные эффекты; небольшие визуальные эксперименты.

> «Сделай для hero мягкий анимированный shader в цветах нашего бренда».

Или:

> «Сделай интерактивную анимацию появления карточек».

Anthropic прямо описывает Claude Code как инструмент для создания custom shaders, procedural animation и других generative systems.

#### 11. Генеративные плагины для Figma

Уровень выше обычного плагина: многоразовый генератор прямо в Figma.

> «Сделай генератор, который по заданным параметрам создаёт варианты иллюстраций-паттернов для обложек в нашем стиле».

Один раз описала, потом вся команда генерирует обложки, паттерны и баннеры в Figma по кнопке.

#### 12. Code Connect: разработчик видит настоящий код компонента

> «Свяжи наши компоненты в Figma с компонентами в коде».

В Dev Mode разработчик видит не сгенерированный CSS, а ваш настоящий компонент с нужными свойствами. Разговоры «а у нас такой кнопки нет» и «зачем ты верстал заново» заканчиваются.

#### 13. Все экраны продукта — на одной доске

> «Пройди по всем страницам нашего продукта, сделай скриншоты и разложи их на доске FigJam по разделам».

Карта всего продукта, какой он сейчас в продакшене. Лучшая отправная точка для аудита, редизайна или онбординга нового дизайнера в команду.

#### 14. Figma tokens vs dev tokens

> «Сравни переменные в Figma с токенами в коде. Покажи, где разошлись, и предложи, как синхронизировать».

#### 15. Реалистичные данные для макетов

> «Сгенерируй 50 профилей для макета: разная длина имён, пустые поля, длинные email, разные страны, аватары с фото и без».

И сразу подставить в Figma. Макет перестаёт выглядеть идеальным и начинает выглядеть как в жизни.

#### 16. Пакет навыков для всей команды 🔥

Ваш чек-лист дизайн-ревью, правила текстов, связка Figma + Jira → упаковывается в плагин команды. Коллега ставит его один раз и получает все ваши процессы.

#### 17. Несколько задач параллельно

Можно открыть несколько сессий одновременно: одна делает прототип, вторая разбирает ресёрч, третья чистит файл Figma.

#### 18. Визуальная проверка изменений разработчиков

> «Возьми ветку с изменениями разработчиков, запусти её и сделай скриншоты ключевых страниц до и после. Покажи, что изменилось визуально».

Дизайнер видит, что поменялось в интерфейсе до релиза, а не когда пользователи уже жалуются.

#### 19. iOS и SwiftUI в обе стороны

Для мобильных команд: Claude переводит макет Figma в SwiftUI и обратно, экраны из SwiftUI-кода — в Figma.

### Приёмы, которые делают Claude Code сильнее

1. **Задача работает, пока ты не за компьютером.** Длинную задачу можно запустить в облаке, закрыть ноутбук, и она продолжит работать. Следить и отвечать на вопросы Claude можно с телефона.
2. **Бриф папки (CLAUDE.md).** В папке проекта лежит файл-бриф: что за проект, какие правила, какая дизайн-система. Claude читает его при каждом запуске. Первый раз попроси: «Изучи папку и составь бриф» (команда /init). Это как инструкции проекта в чате, только для Claude Code.
3. **Навыки вкуса.** Можно установить готовые навыки (скиллы), которые учат Claude хорошему дизайну: запрет на типичный AI-стиль, правила типографики, сетки.
4. **Делиться по ссылке.** Готовый прототип можно опубликовать как страницу по ссылке и скинуть команде, без хостинга и разработчиков.
5. **Передача из Claude Design и обратно.** Проект из Design приходит в Code готовым пакетом, а /design-sync отправляет дизайн-систему из кода обратно в Design.

### Честно об ограничениях

- **Первые 15 минут непривычно.** Интерфейс похож на чат, но Claude реально меняет файлы. Начни с копии или пустой папки.
- **Код для продукта — только через разработчиков.** Прототипы и тулзы делай свободно, а в продуктовый код — только через их ревью.
- **Лимиты общие с чатом и Design.** Большие задачи тратят много.
