# Claude Code

## тут должен был быть смешной тайтл

**Простыми словами:** тот же Claude, но ему можно дать папку. Он в ней сам создаёт и меняет файлы, запускает то, что сделал, и проверяет результат. Пишешь ему по-русски, как в чате. Код читать не нужно.

**Где:** десктоп-приложение Claude → вкладка Code → выбираешь папку → пишешь задачу. Терминал не нужен.

**Почему дизайнеру:** в чате Claude советует, в Claude Code он делает — в Figma, в файлах, в браузере, в коде продукта.

### Сценарии

#### 1. Код → в Figma слоями 🔥

> «Вот наш сайт (или страница из репозитория). Перенеси её в Figma: нашими компонентами и переменными, с автолейаутом».

**Вау:** не картинка, а редактируемый макет из вашей библиотеки. Актуальный продакшен в Figma за минуты, а не «макеты устарели ещё в прошлом году».

#### 2. Figma → работающий фронтенд

> «Сверстай этот фрейм [ссылка на Figma] с нашими токенами и компонентами».

С Figma-коннектором Claude видит устройство макета (слои, автолейаут, переменные), а не картинку. Результат ближе к макету, чем любая вёрстка по скриншоту.

#### 3. Массовые операции в Figma 🔥

> «Переименуй все слои в файле по нашей конвенции».
>
> «Создай переменные из этого JSON с токенами, со светлой и тёмной темой».
>
> «Сделай компонент кнопки со всеми вариантами: размеры, состояния, иконка слева/справа».

**Вау:** работа на день для DS-команды делается за время, пока ты пьёшь кофе. У тебя уже установлен плагин Figma для Claude Code с готовыми навыками именно для этого.

#### 4. Свой плагин для Figma 🔥

> «Сделай плагин для Figma, который проверяет контраст всех текстов на выделенном фрейме и подсвечивает проблемные».

**Вау:** дизайнер сам делает себе плагины без разработчиков. Заполнение реалистичными данными, проверка отступов, экспорт по вашим правилам — всё, чего не хватает в сторе плагинов.

#### 5. Сам поправить UI в продукте

> «В репозитории продукта поменяй отступ у карточки на 16 и текст кнопки на "Сохранить изменения". Покажи, как выглядит».

Claude вносит правку, показывает результат в браузере и готовит изменения на ревью разработчикам.

**Вау:** визуальные мелочи из бэклога, которые «никогда не доходят до спринта», дизайнер закрывает сам. Обязательно договоритесь с разработкой о процессе: правки идут через их ревью, а не напрямую в продукт.

#### 6. Прототип, который проверяет сам себя

> «Сделай прототип оформления заказа. Потом открой его в браузере, пройди все сценарии и исправь, что сломано».

Claude открывает свой прототип во встроенном браузере, кликает, смотрит скриншоты, находит, что кнопка уехала, и чинит. Тебе приходит уже проверенный результат.

#### 7. Три направления одновременно

> «Сделай три версии главной параллельно: минималистичную, редакционную и плотную. Покажи рядом».

Claude запускает нескольких помощников одновременно, каждый делает своё направление. Три варианта за время одного.

#### 8. Ресёрч-конвейер из папки

Папка с 30 расшифровками интервью:

> «Разбери все интервью, найди боли с цитатами, собери аффинити-карту в FigJam и отчёт в виде документа».

**Вау:** от сырых файлов до доски в FigJam и отчёта одной задачей.

#### 9. Рутина с ассетами

> «Вот 400 иконок SVG: оптимизируй, переименуй по конвенции, разложи по категориям, сделай страницу-превью».

Скучная работа на день превращается в одну фразу.

#### 10. Регулярные задачи по расписанию

> «Каждое утро понедельника собирай новые отзывы о приложении и присылай сводку: что сломалось, на что жалуются, что хвалят».

#### 11. Анимации прямо в Figma 🔥

> «Анимируй этот фрейм: карточки появляются по очереди, кнопка пульсирует, переход к следующему экрану. Экспортируй в видео».

Claude через коннектор ставит ключевые кадры и кривые анимации в самой Figma и может выгрузить результат в видео. **Вау:** моушн без After Effects, прямо в файле, где живёт дизайн.

И в обратную сторону: анимацию из Figma переводит в код с теми же таймингами. Больше никакого «сделайте плавненько».

#### 12. Шейдеры в Figma 🔥

> «Сделай для фона шейдер: мягкий переливающийся градиент с шумом, в наших цветах».

Процедурные эффекты и заливки (живые градиенты, шум, стекло, искажения), которые раньше требовали кода или сторонних инструментов, теперь собираются в Figma словами.

#### 13. Генеративные плагины для Figma

Уровень выше обычного плагина: многоразовый генератор прямо в Figma.

> «Сделай генератор, который по заданным параметрам создаёт варианты иллюстраций-паттернов для обложек в нашем стиле».

Один раз описала, потом вся команда генерирует обложки, паттерны и баннеры в Figma по кнопке.

#### 14. Code Connect: разработчик видит настоящий код компонента

> «Свяжи наши компоненты в Figma с компонентами в коде».

**Вау:** в Dev Mode разработчик видит не сгенерированный CSS, а ваш настоящий компонент с нужными свойствами. Разговоры «а у нас такой кнопки нет» и «зачем ты верстал заново» заканчиваются.

#### 15. Все экраны продукта — на одной доске

> «Пройди по всем страницам нашего продукта, сделай скриншоты и разложи их на доске FigJam по разделам».

**Вау:** карта всего продукта, какой он сейчас в продакшене. Лучшая отправная точка для аудита, редизайна или онбординга нового дизайнера в команду.

#### 16. Синхронизация токенов Figma ↔ код

> «Сравни переменные в Figma с токенами в коде. Покажи, где разошлись, и предложи, как синхронизировать».

**Вау:** находит расхождения вроде «в Figma primary уже новый синий, а в коде старый» до того, как их увидит пользователь.

#### 17. Реалистичные данные для макетов

> «Сгенерируй 50 профилей для макета: разная длина имён, пустые поля, длинные email, разные страны, аватары с фото и без».

И сразу подставить в Figma. Макет перестаёт выглядеть идеальным и начинает выглядеть как в жизни.

#### 18. Пакет навыков для всей команды 🔥

Ваш чек-лист дизайн-ревью, правила текстов, связка Figma + Jira → упаковывается в плагин команды. Коллега ставит его один раз и получает все ваши процессы.

**Вау:** опыт лучшего дизайнера команды превращается в инструмент, которым пользуются все одинаково.

#### 19. Задача работает, пока ты не за компьютером

- Длинную задачу можно запустить в облаке, закрыть ноутбук, и она продолжит работать.
- Следить и отвечать на вопросы Claude можно с телефона.
- Когда задача закончена, приходит уведомление.

Поставила перед уходом «разобрать 40 интервью и собрать доску», утром всё готово.

#### 20. Несколько задач параллельно

Можно открыть несколько сессий одновременно: одна делает прототип, вторая разбирает ресёрч, третья чистит файл Figma. Ты переключаешься между ними, как между вкладками.

#### 21. Визуальная проверка изменений разработчиков

> «Возьми ветку с изменениями разработчиков, запусти её и сделай скриншоты ключевых страниц до и после. Покажи, что изменилось визуально».

**Вау:** дизайнер видит, что поменялось в интерфейсе до релиза, а не когда пользователи уже жалуются.

#### 22. iOS и SwiftUI в обе стороны

Для мобильных команд: Claude переводит макет Figma в SwiftUI и обратно, экраны из SwiftUI-кода — в Figma. Удобно, когда iOS-приложение ушло вперёд, а макеты отстали.

#### 23. Режим «объясняй, что делаешь»

В Claude Code можно включить стиль ответов, в котором Claude объясняет свои действия простыми словами по ходу работы. Для дизайнеров, которые хотят постепенно начать понимать код, это мягкий способ учиться на своих же задачах.

#### 24. Командные тулзы с общими данными

Claude Code может сделать и опубликовать по ссылке инструмент, который хранит данные для всех: база инсайтов с тегами, голосовалка за концепты, трекер дизайн-долга. Каждый в команде открывает ссылку и видит одно и то же.

#### 25. Голосом

Диктовка работает и здесь. Длинную задачу для Claude Code удобнее надиктовать, как брифуешь коллегу.

### Приёмы, которые делают Claude Code сильнее

1. **Режим планирования.** Переключи режим на Plan (в поле ввода, или Shift+Tab). Claude сначала показывает план, что и как собирается делать, и ничего не трогает, пока ты не одобришь. Для дизайнера это самое важное: видишь замысел до того, как что-то изменилось.
2. **Откат назад.** Сделал не то? Можно вернуться к любому моменту разговора, и файлы откатятся тоже (двойной Esc или меню отката). Можно смело экспериментировать.
3. **Бриф папки (CLAUDE.md).** В папке проекта лежит файл-бриф: что за проект, какие правила, какая дизайн-система. Claude читает его при каждом запуске. Первый раз попроси: «Изучи папку и составь бриф» (команда /init). Это как инструкции проекта в чате, только для Claude Code.
4. **Навыки вкуса.** Можно установить готовые навыки (скиллы), которые учат Claude хорошему дизайну: запрет на типичный AI-стиль, правила типографики, сетки. У тебя, кстати, уже установлен набор taste-skill. Прототипы с ним выглядят заметно менее шаблонно.
5. **Скриншот прямо в сообщение.** Вставляешь скриншот (Ctrl+V): «сделай вот так» или «вот тут сломалось». Работает так же, как в чате.
6. **Делиться по ссылке.** Готовый прототип можно опубликовать как страницу по ссылке и скинуть команде, без хостинга и разработчиков.
7. **Передача из Claude Design и обратно.** Проект из Design приходит в Code готовым пакетом, а /design-sync отправляет дизайн-систему из кода обратно в Design.

### Честно об ограничениях

- **Первые 15 минут непривычно.** Интерфейс похож на чат, но Claude реально меняет файлы. Начни с копии или пустой папки.
- **Код для продукта — только через разработчиков.** Прототипы и тулзы делай свободно, а в продуктовый код — только через их ревью.
- **Лимиты общие с чатом и Design.** Большие задачи тратят много.
