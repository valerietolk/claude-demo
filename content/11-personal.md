**Claude Code vs Claude Design**

Лично у меня Claude Code чаще даёт результат приятнее, чем Claude Design — при одинаковых условиях теста.

Ещё более важная разница: в Code проще осознать, что шальная дизайнерская мысль действительно реализуема силами фронтенда.

**Локальные файлы ≠ облако**

По умолчанию Claude Code работает с файлами локально на твоём компьютере.

Если хочешь продолжить работу с другого устройства, сохраняй проект в GitHub или другом подходящем хранилище. Для облачных сессий GitHub особенно удобен: облачный Claude берёт проект из репозитория, а не из твоего ноутбука.

если не хотите стать рабом раба — сразу поставь ограничения на расход.

**Claude Design не становится Figma.** Даже подключённая дизайн-система не делает его полноценной заменой Figma: изменения не становятся автоматически источником правды для всех предыдущих результатов и диалогов.

</div>

- **Сохраняйся, как в игре.** «После каждого удачного шага делай commit». Что-то сломал — откатываешься к последнему хорошему сохранению, а не ведёшь переговоры с машиной в стиле «пожалуйста, верни как было».
- **Запреты в брифе папки.** В CLAUDE.md напиши «не трогай папку X, не меняй цвета без спроса». Он читает это при каждом запуске, и одни и те же косяки не повторяются.

### Claude Code в облаке

Это тот же Claude Code, только задача выполняется на виртуальном компьютере Anthropic.

Можно:

- закрыть ноутбук — задача продолжит работать;
- запускать несколько задач параллельно;
- следить за работой с другого устройства;
- продолжать с телефона.

#### Сценарий «мысль в метро»

1. Открываешь Claude → Code.
2. Выбираешь репозиторий.
3. Надиктовываешь задачу.
4. Claude работает сам.
5. Получаешь уведомление, если ему нужен ответ.
6. Дома открываешь результат и продолжаешь.

Для этого особенно удобно иметь отдельный репозиторий-песочницу вроде prototypes, куда можно складывать все шальные дизайнерские эксперименты.

<p class="callout">Но: облачная сессия работает с копией проекта на серверах Anthropic. NDA-код, внутренние продукты и чувствительные материалы — только если это разрешено политикой компании.</p>

#### 2. Сложные SVG-фильтры (жидкое стекло)

Сами SVG-фильтры работают везде давно. Но эффект «жидкого стекла» с преломлением того, что под элементом (как в Apple Vision Pro или iOS 26) делается связкой, которая полноценно работает только в Chrome. В Safari (иронично, у Apple) и Firefox получится только обычное размытие.

Плюс производительность: такие фильтры на большой площади или в анимации ощутимо грузят слабые устройства.

<p class="fact"><b>Вывод:</b> стекло с размытием — можно. «Настоящее» жидкое стекло с преломлением — пока только как вау-концепт или с запасным вариантом для остальных браузеров.</p>

#### 4. WebGL

WebGL открывает почти 3D-мир:

- 3D-модели;
- интерактивные сцены;
- частицы;
- сложные эффекты.

**Пример.** Сайт Tesla. Ты открываешь страницу машины:

- крутишь автомобиль;
- меняешь цвет;
- камера плавно летает вокруг.

Это может использовать WebGL.

Но вместе с этим приходят сложность разработки, тестирования и производительности.

Для сайта продукта это иногда оправдано.

Для обычного лендинга с кнопкой "Купить" — это просто дизайнерский фейерверк, который пришёл без приглашения.
